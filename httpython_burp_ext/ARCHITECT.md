# httpython 仕様書

BurpSuite 拡張。キャプチャした HTTP リクエストを、`requests` モジュールを使った Python 関数に変換・生成する。

---

## 1. 概要

Proxy history や Repeater で捕捉した HTTP リクエストを httpython タブに転送し、そこで
`requests` モジュールを使用した Python 関数へ変換・出力する拡張である。

生成されるコードは以下を満たす。

- リクエストの送信先ホストは関数の第一引数 `base_url` から受け取る。
- 任意のクエリパラメータ・ボディパラメータ・ヘッダを関数の引数として外出しできる。
- HTTP レスポンスから任意の値を抽出して返す。単純な JSON キー指定に加え、CSRF トークン抽出などの複雑な取り出しにも対応する。
- 送信は必ずプロキシ経由とする。プロキシ URL は httpython タブで設定し、生成コード内にグローバル定数 `PROXIES` として埋め込む。**この値が未設定の場合はコードを生成できない。**
- 複数リクエストをまとめて 1 スクリプトへ変換できる。

---

## 2. 用語定義

| 用語 | 定義 |
| --- | --- |
| httpython タブ | 本拡張が追加する専用タブ。転送されたリクエストの管理とコード生成を行う。 |
| Send to httpython | Proxy history / Repeater 等のコンテキストメニューに追加される転送アクション。 |
| 変換対象リクエスト | httpython タブに転送され、関数化の対象となる 1 件の HTTP リクエスト。 |
| パラメータ化 | リクエスト中の値（クエリ/ボディ/ヘッダ）を、リテラルではなく関数の引数として受け取る形に変換すること。 |
| 抽出ルール | レスポンスから関数の返り値を取り出す方法の定義。 |
| PROXIES | 生成コードのグローバルスコープに定義するプロキシ設定定数。 |

---

## 3. 全体フロー

```
[Proxy history / Repeater]
        │  右クリック → Send to httpython
        ▼
[httpython タブ：リクエスト一覧]
        │  リクエストを選択
        ▼
[変換設定パネル]
   ・base_url の切り出し（自動）
   ・クエリ / ボディ / ヘッダのパラメータ化
   ・返り値の抽出ルール設定
        │
        ▼
[プロキシ URL 設定]（未設定なら生成不可）
        │  Generate
        ▼
[Python コード出力]（コピー / 保存）
```

## 4. 機能要件

### 4.1 Send to httpython（リクエスト転送）

- Proxy history、Repeater をはじめ、`HttpRequestResponse` を保持する画面のコンテキストメニューに **Send to httpython** を追加する。
- 選択したリクエストを httpython タブのリクエスト一覧へ追加する。
- 複数選択された状態からの一括転送に対応する（→ 4.4）。
- 転送時、リクエストのメソッド・URL・ヘッダ・ボディを保持する。

### 4.2 リクエスト一覧・選択

- 転送されたリクエストを一覧表示する（メソッド、ホスト、パスなどを列表示）。
- 一覧から任意のリクエストを選択すると、変換設定パネルに内容が反映される。
- 一覧からの削除・並べ替えに対応する（並び順は生成スクリプト内の関数定義順に対応する）。

### 4.3 関数変換設定

選択したリクエストを 1 つの Python 関数へ変換する。関数の骨子は次の通り。

```python
def <func_name>(base_url, <parameterized_args...>):
    res = requests.<method>(base_url + "<path>", ...)
    return <extracted_value>
```

#### 4.3.1 base_url（必須・固定仕様）

- リクエストの `scheme://host[:port]` 部分を `base_url` として切り出し、**常に関数の第一引数**とする。
- URL は `base_url + "<残りのパス+クエリ>"` の形で組み立てる。
- `base_url` はパラメータ化設定の対象外（常に第一引数で固定）。

#### 4.3.2 パラメータ化（クエリ / ボディ / ヘッダ）

- リクエスト中のクエリパラメータ・ボディパラメータ・ヘッダの各項目について、ユーザが個別に「リテラルのまま」か「関数の引数として外出し」かを選択できる。
- 引数として外出しした項目は、関数シグネチャに追加される。引数名の既定値は元のキー名とし、ユーザが変更できる。
- パラメータ化された項目は、生成コード内で対応する引数を参照する形になる。

| 対象 | リテラルの場合 | パラメータ化した場合 |
| --- | --- | --- |
| クエリ | `params={"q": "value"}` | `params={"q": q}` |
| ボディ（JSON） | `json={"username": "admin"}` | `json={"username": username}` |
| ボディ（form） | `data={"user": "admin"}` | `data={"user": user}` |
| ヘッダ | `headers={"X-Token": "abc"}` | `headers={"X-Token": x_token}` |

- 引数の並び順は `base_url` の次に、ユーザが指定した順（既定はクエリ→ボディ→ヘッダの出現順）とする。

#### 4.3.3 返り値の抽出ルール

関数の返り値として、レスポンスのどの部分を採用するかを設定する。
単純なキー指定だけでなく、CSRF トークン抽出のような複雑な取り出しにも対応する。

| 抽出方式 | 生成される式（例） | 用途 |
| --- | --- | --- |
| レスポンスオブジェクト | `return res` | 呼び出し側で自由に扱う |
| ステータスコード | `return res.status_code` | 成否判定 |
| 生テキスト | `return res.text` | HTML/テキスト全体 |
| JSON キーパス | `return res.json()["data"]["token"]` | ネスト・配列インデックス指定に対応 |
| ヘッダ | `return res.headers["Location"]` | リダイレクト先など |
| Cookie | `return res.cookies["session"]` | セッション ID など |
| 正規表現 | `return re.search(r'name="csrf" value="(.+?)"', res.text).group(1)` | HTML 内の CSRF トークン等 |
| カスタム式 | ユーザが記述した任意の Python 式（`res` を参照可能） | 上記で表せない複雑な抽出 |

- **単純設定**：JSON キーパスやヘッダ名など、フィールドを埋めるだけで指定できる方式を用意する。
- **複雑設定**：正規表現・カスタム式により、CSRF トークン抽出や複数レスポンス要素の組み合わせに対応する。カスタム式は最終的なエスケープハッチとして、`res` を変数として使える任意の Python 式を許可する。
- 複数の値を取り出したい場合、複数の抽出ルールを指定し、タプルで返せるものとする（例：`return res.json()["id"], res.cookies["session"]`）。
- 抽出ルールが正規表現・JSON など追加 import を要する場合、生成スクリプト先頭に必要な import を自動付与する。

> 補足：CSRF トークンのようにあるリクエストの返り値を次のリクエストの引数に渡す使い方を想定する。返り値抽出とパラメータ化を組み合わせることで、生成された関数どうしを呼び出し側で連結できる設計とする。

### 4.4 複数リクエスト対応

- 複数のリクエストを httpython タブに転送し、1 つのスクリプトに複数の関数として出力できる。
- 各リクエストの変換設定（パラメータ化・抽出ルール・関数名）は独立して行う。
- 関数名が重複する場合は生成前に警告し、重複のまま生成しない。
- `PROXIES` 定数はスクリプト内に 1 つだけ定義し、全関数で共有する。

### 4.5 プロキシ設定（PROXIES）

- httpython タブにプロキシ URL の設定欄を設ける。設定値は拡張内で保持する。
- 生成コードのグローバルスコープに定数 `PROXIES` を出力し、全リクエストで `proxies=PROXIES` を指定する。
- **プロキシ URL が未設定の場合、コード生成を実行できない**（Generate を無効化、または生成時にエラー表示して中断する）。
- URL は `requests` のプロキシ書式（スキーム付き、例 `http://127.0.0.1:8080`）で保持・出力する。

```python
PROXIES = {
    "http": "http://127.0.0.1:8080",
    "https": "http://127.0.0.1:8080",
}
```

## 5. コード生成仕様

### 5.1 生成コードの構造

生成スクリプトは次の順で構成する。

1. 必要な import（`requests`、および抽出ルールに応じて `re` 等）
2. グローバル定数 `PROXIES`
3. 各リクエストに対応する関数定義（一覧の並び順）

すべてのリクエスト送信で以下を固定で付与する。

- `proxies=PROXIES`
- `verify=False`（プロキシ経由での証明書検証を無効化する）

### 5.2 コーディング規約（生成コード）

- **簡潔に書く。** 冗長な中間変数や不要な整形を避ける。
- **コメントは関数にのみ付ける。** その関数が何をするのかを 1 行で記述する。
- **例外：** コードを読んだだけでは意図が分からない箇所に限り、インラインコメントを付けてよい。
- 関数コメントは `def` 直下のコメント行（`#`）または 1 行の docstring とし、スクリプト全体で書式を統一する。

### 5.3 メソッド / ボディのマッピング

- HTTP メソッドは `requests.get` / `requests.post` / `requests.put` / `requests.delete` 等へ対応付ける。
- ボディの表現は Content-Type に応じて選択する。
  - `application/json` → `json=`
  - `application/x-www-form-urlencoded` → `data=`（dict）
  - それ以外（生ボディ） → `data=`（bytes/str）
- クエリは `params=`、ヘッダは `headers=` として出力する。ヘッダは Burp が自動付与するもの（`Content-Length` 等）を除外してよい。

### 5.4 生成例

ログインリクエスト（`POST /login`、JSON ボディ `username` / `password` をパラメータ化、JSON レスポンスの `res` キーを返す）を変換した例：

```python
import requests

PROXIES = {
    "http": "http://127.0.0.1:8080",
    "https": "http://127.0.0.1:8080",
}


# base_url に対してログインし、レスポンス JSON の res を返す
def req(base_url, username, password):
    res = requests.post(base_url + "/login", headers={
        "Content-Type": "application/json"
    }, json={
        "username": username,
        "password": password
    }, proxies=PROXIES, verify=False)
    return res.json()["res"]
```

CSRF トークンを HTML から正規表現で抽出する例：

```python
import re
import requests

PROXIES = {
    "http": "http://127.0.0.1:8080",
    "https": "http://127.0.0.1:8080",
}


# ログインページを取得し、フォーム中の CSRF トークンを返す
def get_csrf(base_url):
    res = requests.get(base_url + "/login", proxies=PROXIES, verify=False)
    return re.search(r'name="csrf_token" value="(.+?)"', res.text).group(1)
```

## 6. UI 仕様

httpython タブは概ね次の構成とする。

- **リクエスト一覧**：転送済みリクエストの一覧。選択・削除・並べ替え。
- **変換設定パネル**（選択リクエストに連動）：
  - 関数名
  - クエリ / ボディ / ヘッダの一覧と、各項目のパラメータ化トグル・引数名入力
  - 返り値の抽出ルール設定（方式選択＋方式ごとの入力欄）
- **プロキシ設定欄**：プロキシ URL 入力（拡張全体で共有）。
- **出力エリア**：Generate ボタン、生成コードのプレビュー、コピー / 保存。
- プロキシ URL 未設定時は Generate を無効化し、その旨を明示する。

---

## 7. バリデーション・エラー処理

| 条件 | 挙動 |
| --- | --- |
| プロキシ URL 未設定 | コード生成不可。理由を明示する。 |
| 関数名が空 / 不正 / 重複 | 生成前に警告し中断する。 |
| パラメータ化した引数名が重複・不正 | 生成前に警告する。 |
| 抽出ルール（正規表現・カスタム式）が空 | 該当方式選択時は必須入力とする。 |
| 変換対象リクエストが 0 件 | 生成不可。 |

---

## 8. 非機能要件・制約

- 対象：BurpSuite 拡張として動作する（コンテキストメニュー登録、専用タブ追加）。
- 生成コードは Python 3 / `requests` で実行可能であること。
- 生成コードは常にプロキシ経由（`proxies=PROXIES`）かつ `verify=False`。
- プロキシ URL・各リクエストの変換設定はセッション中保持する。
